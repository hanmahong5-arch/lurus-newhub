# Cycle 15 — 控制台对标 OpenRouter 的全面提升 (2026-09-22)

## 对标对象与理由

**主对标 = OpenRouter**(openrouter.ai)。理由:它是「一个 API 接全部模型」这一品类的头部产品,
我们的控制台核心页面(模型、排行、用量、令牌、调试台)与它一一对应;它的模型广场/排行榜/
Activity 是该品类公认的标杆。**企业治理面**(日志、审计、网关健康)参考 Helicone / Portkey 的
仪表盘形态(时间范围切换、错误分布、Top 模型)。

约束:品牌色/字体来自平台同步的 `web/src/styles/lurus-design/tokens.css`(`--lt-*`),本轮**不改品牌
token**,只在 `--hf-*` 产品层和组件层提升;前端一律 Bun;每个阶段单独 PR、先本地测透再上 UAT。

## 阶段(每阶段 = 1 个 PR,验证方法写在每条后面)

### P1 视觉地基 + 数据补全(本 PR)
1. D1:中文环境下取消标签类字距(`html[lang^='zh']` 作用域)。验证:截图对比。
2. D2:表头/标签/状态不折行;中文 `word-break: keep-all`。验证:截图对比 Log 页。
3. 供应商图标组件 `HfVendorIcon`(复用 `@lobehub/icons`)。验证:单测渲染 + 截图。
4. D4:渠道类型显示名称 + 图标。验证:单测 + 截图。
5. D6:v2 定价接口补 `completion_ratio`/`description`/`icon`/`tags`。验证:Go 单测(变异:删字段即红)。
6. D5:排行榜空名显示「未识别模型」。验证:单测。

### P2 模型广场(OpenRouter /models)
- 数据 = 可路由模型 ∩ 租户定价 ∪ 元数据:卡片(图标、名称、供应商、描述、输入/输出 $/1M、缓存价、
  能力标签、近 7 天 tokens)、搜索、供应商/能力筛选、排序(名称/价格/热度)、列表/表格切换、
  详情抽屉(价格明细、接入代码、去调试台)。管理员的增删改保留。
- 验证:页面测试断言「可路由但无元数据的模型也出现」(D3 变异:只读元数据即红)+ UAT 截图。

### P3 活动与排行(OpenRouter /activity + /rankings)
- 概览:时间范围 24H/7D/30D;按模型堆叠的每日消费图;Top 模型;最近请求。
- 排行榜:按周堆叠趋势图 + 排行表(份额条、环比)。
- 验证:页面测试 + UAT 截图。

### P4 日志与账单打磨(Helicone 形态)
- 日志:状态分布条、错误码聚合、请求详情分区(请求/响应/计费/链路)。
- 账单:余额卡、消费构成、充值记录时间线。
